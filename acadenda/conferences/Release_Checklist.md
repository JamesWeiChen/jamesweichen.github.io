# 會議接案與發布檢查表

## 目前完成與未完成

- 已完成：Excel 範本、Mac Excel → JSON 工具、格式驗證與版本差異檢查。
- 已完成：靜態議程頁、地圖連結、固定 JSON 連結與 QR Code、最新 JSON 的 AI 修改指令。
- 已完成：中英文介面、淺深色與系統外觀、手機排版與瀏覽器測試。
- 尚待確認：GitHub Pages 正式部署後的網址、QR Code 與快取更新。
- 尚待完成：在 Acadenda 實機上，對同一個網址完成初次匯入、收藏、議程更新與個人資料保留的整套驗收。本次網站測試不能代替 App 驗收。
- 尚未提供：GUI 一鍵建立網站、GUI 新舊 JSON 差異審查、自動發布。目前這些是本機指令與人工確認流程，可先用於少量會議。
- 不包含：熱門度統計、主辦方登入、自助上傳、私密審稿空間。

## 接收會議前

- [ ] 指定主辦方的資料窗口、最終確認人及更新截止時間。
- [ ] 確認主辦方同意公開議程、講者資料與提供的地圖；JSON 網址本身也是公開的。
- [ ] 用一份小型測試資料，走完 Excel → Mac 轉換 → 網頁檢查 → App 匯入 → 同網址更新。
- [ ] 確認日期、當地時間、平行場次、海報、共同作者與地圖能滿足這場會議。跨時區需求須另行驗證，不能假設已支援。
- [ ] 如需私下檢查未公開內容，先採本機預覽或私下提供檔案；GitHub Pages 的未列出連結不是存取權限控制。

## 每屆首次發布

- [ ] 決定唯一且不重複使用的 `edition_key`、JSON 檔名與會議頁 slug；不同屆不得沿用同一組。
- [ ] 發送空白 Excel 與欄位說明。場次與演講代碼一經分配，之後不得為了排序重新編號。
- [ ] 收到 Excel 後用 Mac 工具轉換，解決格式錯誤；不知道的時間不可自行推算。
- [ ] 以主辦方原始資料核對天數、場次數、演講數、講者、主持人、會場與時間。
- [ ] 確認主辦方認可頁面內容，保存確認紀錄。
- [ ] 建立專屬頁面，檢查 JSON 與 QR 都指向正確且固定的網址。
- [ ] 提交發布版本並推送，確認 GitHub Pages 部署成功，從正式網址開啟頁面。
- [ ] 在 App 透過正式 JSON 連結及 QR Code 匯入，確認議程、地圖與時間。

## 同一場會議更新

- [ ] 保存主辦方明確的修改要求；不清楚是改題目還是替換另一篇論文時先確認。
- [ ] 用網頁按鈕複製最新 JSON 與規則，請 AI 只處理指定變更。
- [ ] 將回覆存成新檔，執行 `validate 新版.json --previous 舊版.json`，人工核對新增、刪除、欄位與 ID 差異。
- [ ] 主辦方確認後，替換同名 JSON；不改匯入網址，不因排序或改時間而重新生成 ID。
- [ ] 發布後在 App 更新既有會議；確認收藏、個人筆記與其他使用者狀態符合 App 預期。
- [ ] 若發布錯誤，在 Git 中還原該次 JSON 修改並重新發布；完成後確認正式網址已回到正確內容。

## 維護紀錄

每場會議記錄：主辦方窗口、屆次鍵、正式 JSON 網址、會議頁網址、確認日期、發布 commit 與修改摘要。
私人聯絡紀錄與未公開需求應留在私有位置，不要提交到公開網站儲存庫。

這份清單是人工營運流程，不代表網站會自動執行這些檢查。
